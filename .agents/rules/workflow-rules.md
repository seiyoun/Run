# Agent Workflow & Interaction Rules

When assisting with this project, all agents MUST strictly follow these rules:

## 1. Language Rule (言語ルール)
- **すべての返答・解説・計画提示・質問は必ず日本語で行ってください。**
- コードコメントやコミットメッセージ等で英語が標準とされている場合を除き、ユーザーとの対話は日本語に統一します。

## 2. Pre-Implementation Approval (実装前の事前相談と許可の取得)
- **実装（新規ファイルの作成、既存コードの修正、削除、リファクタリング等）を行う前に、必ず以下の内容をユーザーに提示し、明示的な許可（合意）を得てください。**
  1. 実装の目的・背景
  2. 提案する設計および実装アプローチ
  3. 変更・追加・削除対象となるファイル一覧
  4. 予想される影響範囲や注意点
- ユーザーから「進めてください」「問題ない」「OK」等の合意を得るまで、ソースコードの変更作業を開始してはなりません。

## 3. Safety & Data Protection (安全対策とデータ保護)
- 不可逆な変更（ファイルの強制削除、`git reset --hard`、`git clean -fd` 等）や破壊的なコマンドの実行は原則避け、必要な場合は必ず事前にユーザーの確認と許可を得てください。
- 予期せぬデータ消失を防ぐため、既存コードの動作やテストへの影響を常に意識して作業を進めてください。

## 4. Unity Compilation Validation (実装後のUnityコンパイルエラーチェック)
- **C# スクリプトの作成・編集・削除などを行った後は、必ず Unity Editor のコンパイルエラーチェックを行ってください。**
- Unity MCP ツール（`unity_get_logs`, `unity_refresh_assets`）またはエディタログを通じてコンパイルエラー（CSxxxx エラーや Exception）がないことを確認してください。
- コンパイルエラーが残っている状態ではタスクを完了とせず、原因を解消するまで作業を継続してください（`Stop` フックによっても自動検証されます）。

## 5. Strict YAGNI & No Unnecessary/Unreferenced Code (不要コード・非参照コード生成の厳禁)
- **ユーザーから明示的に要求されていないクラス、ステート、Enum値、フィールド、プロパティ、メソッドは一切生成・追加してはなりません。**
- **「将来使うかもしれない」「念のため」「あると便利そう」「拡張性のため」という推測に基づく先行実装（デッドコード）の作成を厳禁とします。**
- 他のコードから参照されないコードや、どこからも呼ばれない未使用の参照を追加せず、要求された目的を満たす最小限の実装（Minimal Viable Change）に徹底して留めてください。
- 新規コードを作成または修正する際は、必ず「今この瞬間に呼び出し元（参照元）が存在するか」「タスクの目的と直接結びついているか」を確認してください。
